You use AI at work. Who checks the answer?

With the AI under your control method, you choose where it works, who sees your data, and what proof it must provide before you trust it.

Understand the choicesTry the exercise

In brief

This is a free decision and verification kit for people who use AI at work. It separates two choices: who can access the data and which requests the model agrees to answer. The kit includes an exercise with a known answer, a fillable form, and a local checker for recording your decisions. You only need to read to understand the subject; to run the checker, you need Python. It does not install or configure AI models.

Learn with Nei

The explainer video is in production. You can already explore the analysis and exercise below.

Freedom, privacy, and accuracy are different choices

Think of an employee with access to the office: speaking frankly, storing documents, and doing accurate calculations are distinct abilities.

Uncensored AI

It concerns response restrictions: the model was selected or modified to refuse fewer requests. It may run locally or through an external provider. This does not guarantee privacy or accuracy.

Private AI

It concerns who can access your data. Running AI on your own device is one option, as long as the task does not send content to external services. A private AI may still refuse requests.

More confidence

It comes from checking: recalculating, comparing with original data, and running tests. Two models agreeing still is not proof.

This repo provides a decision and verification kit. It helps you assess privacy, freedom of response, and quality separately. It does not install a private AI or an uncensored model.

What the five levels actually change

The lesson brings together five paths. Each addresses a need; you can combine the ones that make sense.

1 · Model
Change the engine that respondsUse a model with fewer refusals in a work interface. The interface and the model are different components: changing the engine changes capabilities, context, and compatibility with tools. This analysis does not change your Claude Code or Codex configuration.
2 · Review
Ask another person or model to checkThis helps find failures, as long as the reviewer has access to the data and a clear completion criterion. Asking another model the same question may repeat the error.
3 · Access
Keep it available on a serverA VPS is a rented computer that can stay on. Tailscale connects your devices on a private network. Neither alone guarantees that the agent will do the right task or that the service will never stop.
4 · Media
Generate images and videoVenice and other providers process content on the chosen infrastructure. Draw Things allows local generation on Apple devices and also offers cloud processing. Check which mode is active before sending private material.
5 · Local
Bring the model to your computer or phoneOllama and PocketPal are options for local execution. Download the model first, check memory, and test your task with the network disconnected. A small model does not inherit the capabilities of a large one just because it runs offline.

Tools, models, and offers change. We do not repeat discounts, prices, or performance claims from the lesson as results measured by INEMA.

The test that shows whether AI checked its work

Use the same task before switching models. The figures below are fictional, and you can check the answer by hand.

The prompt

January: revenue of R$ 120 thousand, expenses of R$ 90 thousand. February: revenue of R$ 100 thousand, expenses of R$ 110 thousand. What was the result for each month and for the two-month period? Did revenue grow?

The reference answer

January: +R$ 30 thousand. February: −R$ 10 thousand. Two-month period: +R$ 20 thousand. Revenue fell approximately 16.67% from January to February. Compare the calculations, not how confident the answer sounds.

Ask the first model to answer. Give the reviewer the original data and the answer. Finally, compare both with the reference above. Record errors, time, and what needed correcting. This exercise is a demonstration with an answer key, not a comprehensive quality test.

Start with your needs

Want to work without internet?

Download a compatible model, load it on your computer or in PocketPal, and test it in airplane mode. Check the tools too: search and external services need a network connection.

Want to use it away from home?

Keep your computer available or use a VPS. Restrict access through the private network and check permissions; costs and maintenance still apply.

Want fewer refusals?

Compare models using your task. Also check quality, language, and tools. “Abliterated” describes an intervention to reduce refusals; it is not a trustworthiness label.

Want to work with private documents?

Map the file's path through to the answer. Review syncing, history, and external tools. Use a fictional copy for the first test.

From your choice to a checked form

Python 3.10 or later and Git. No extra libraries, account, key, or model call. The commands below work in the Linux, macOS, or Windows terminal with Python installed; on Windows, replace python3 with py if needed.

Prepare the computer

Install Python 3.10 or later and Git using your system’s installers. On Windows, enable the option to add Python to PATH during installation. On macOS, use the official installers; on Ubuntu, you can install the packages below. If the version commands already work, continue to step 1.

python3 --version
git --version

Ubuntu, if they are still missing:

sudo apt update
sudo apt install python3 git

How to fill out the form

JSON is a text file organized by names and values. Keep the quotation marks around text and the commas between fields. In the evidence fields, true means yes and false means no, without quotation marks. The example below is only a demonstration of how to fill it out, not evidence from a real test. Replace the model with the name you actually used, and mark yes only after checking.

{
  "objetivo": "Conferir o relatório fictício",
  "dados": "sinteticos",
  "execucao": "local",
  "modelo": "modelo-demonstracao",
  "ferramentas": "nenhuma",
  "revisao": "humana",
  "acesso": "somente-dispositivo",
  "offline_necessario": true,
  "evidencias": {
    "sem_rede": true,
    "resultado_conferido": true,
    "permissoes_conferidas": true
  }
}

Accepted options for each field appear in the checker’s output if you enter an invalid value. The kit’s files and messages are in Portuguese.

2

Edit the form with your actual configuration details

Open the file below in an editor. The model name starts as a placeholder, and the evidence fields start as false: the example is expected to need correction. Use only true or false without quotes in the evidence fields.

kit/exemplos/ficha.json

Fields: goal; data sensitivity; local, VPS, or provider execution; model; tools; reviewer; access; offline requirement; verification evidence.

3

Run the checker

python3 scripts/conferir.py kit/exemplos/ficha.json

invalida output (code 2): missing or invalid field. revisar (code 1): evidence is missing or there is a contradiction. ficha-conferida (code 0): the declared form is consistent; read the warnings too.

This program does not inspect your machine, verify the truth of what you selected, or certify privacy. It helps you remember decisions.
